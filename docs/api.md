# JSON API contract

## Shared rules

- Every route except `/health` requires `Authorization: Bearer <lab token>`.
- Mutation bodies carry `requestKey`; exact intent replays the original status/result and changed intent returns `409` with
  `intent_conflict`.
- Bucket names use `^[a-z0-9][a-z0-9-]{1,30}[a-z0-9]$`. Keys are bounded synthetic identifiers and never become paths.
- Bodies are generated from a fixed pattern and repeat count. Arbitrary uploads and public network access are not supported.
- Success responses return an `evidence` object. They never use `durable`, `backedUp`, `restored`, `consumed`, or `accepted` as an
  unqualified boolean.
- Errors are `{ "error": { "code": "...", "message": "..." } }` with no secret, SQL, key, digest, path, or object body.

## Generated bytes

```json
{
  "pattern": "alpha",
  "repeat": 64
}
```

`pattern` is one of `alpha`, `beta`, `gamma`, or `delta`; `repeat` is a positive integer. The service expands a fixed public
synthetic pattern, rejects results above 65,536 bytes, and hashes the exact bytes. This is a test fixture, not a streaming upload.

## Routes

### `POST /v1/buckets`

```json
{ "requestKey": "req-bucket-001", "bucket": "lab-bucket" }
```

Returns one bucket creation receipt. Existing bucket plus exact request replays; a separately keyed duplicate name conflicts.

### `PUT /v1/objects`

```json
{
  "requestKey": "req-put-001",
  "bucket": "lab-bucket",
  "key": "reports/day-001",
  "content": { "pattern": "alpha", "repeat": 64 },
  "ifCurrentVersionId": null
}
```

Returns `versionId`, `versionSequence`, `contentDigest`, `byteLength`, `placementGeneration`, `verifiedReplicas`,
`requiredReplicas`, and evidence flags for metadata commit and same-host readback. `ifCurrentVersionId` can contain an exact version
ID or the sentinel `absent`; mismatch is `precondition_failed`.

### `POST /v1/object-reads`

```json
{
  "bucket": "lab-bucket",
  "key": "reports/day-001",
  "versionId": null,
  "range": { "start": 4, "endExclusive": 20 }
}
```

Returns selected version evidence and `bodyBase64`. The service verifies the full object before slicing. Omitting `versionId`
selects the current pointer; omitting `range` returns the full bounded object. This is not HTTP Range compatibility.

### `DELETE /v1/objects`

```json
{
  "requestKey": "req-delete-001",
  "bucket": "lab-bucket",
  "key": "reports/day-001",
  "ifCurrentVersionId": "ver_..."
}
```

Creates a tombstone version. Current read becomes `current_tombstone`; explicit retained data versions remain readable.

### `POST /v1/list-snapshots`

```json
{
  "requestKey": "req-list-001",
  "bucket": "lab-bucket",
  "prefix": "reports/",
  "includeTombstones": false
}
```

Returns `snapshotId`, `itemCount`, and the first page. `GET /v1/list-snapshots/{id}?offset=0&limit=16` returns only materialized
items and a numeric `nextOffset`; it never queries current heads.

### Multipart

- `POST /v1/multipart-uploads`: stable request, bucket/key, `expectedParts` 1–4, expiry generation.
- `PUT /v1/multipart-parts`: stable request, upload ID, part number, generated bytes. Changed bytes at the same part number conflict.
- `POST /v1/multipart-completions`: stable request, upload ID, exact ordered `parts` array, optional current-version precondition.
- `POST /v1/multipart-aborts`: stable request and upload ID. A completed/aborted/expired upload cannot change state.

Completion returns the same object-version receipt as PUT plus the immutable upload result.

### Maintenance

- `POST /v1/repairs`: task ID and expected placement/maintenance generations; one target per call.
- `POST /v1/orphan-scans`: expected maintenance generation and minimum age; returns counts plus opaque scan ID.
- `POST /v1/gc-runs`: expected generation, scan ID, retention cutoff; deletes only freshly rechecked unreachable files.
- `POST /v1/maintenance-generations`: advances one bounded worker kind for explicit stale-worker tests.
- `GET /v1/state`: low-cardinality counts and explicit `backupRestoreProved: false`, `externalAcceptanceProved: false`.

## Status mapping

| Code | HTTP |
|---|---:|
| success / replay | 200 or 201 |
| invalid input / capacity exceeded | 400 or 413 |
| unauthorized | 401 |
| not found / current tombstone | 404 |
| intent conflict / precondition / closed upload / stale generation | 409 |
| integrity failure / replica threshold not met | 503 |
| internal error | 500 |

The exact implementation supports a deliberately small subset documented by its tests. This page is not an OpenAPI or provider
compatibility promise.
